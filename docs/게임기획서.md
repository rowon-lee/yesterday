# [가제] YESTERDAY 스틱 액션 — 게임 기획서

Oct 30, 2026 · @주호영

## 개요

YESTERDAY 세계관의 히어로·빌런이 되어 싸우는 도트 액션 게임이다. 블리치 vs 나루토처럼 버튼은 적고 콤보와 기술이 화려한 전투를, 두 가지 모드로 즐긴다.

| 항목 | 내용 |
| --- | --- |
| 장르 | 옆에서 보는 2D 도트 액션 (블리치 vs 나루토식 전투) |
| 세계관 | YESTERDAY · 2140년 뉴 샌디에이고, 세상이 망한 뒤 20세기 초 미국 도시풍으로 새로 지은 디스토피아 도시 |
| 모드 | 대련(1:1 온라인 대전), 마수 토벌(3인 편성 로그라이트) |
| 그림 | 코드로 그린 굵은 선 스틱맨 + 장식 + 픽셀 이펙트 |
| 규격 | 화면 320×180, 캐릭터 칸 64×64, 동작당 12~14프레임, 1초 60틱 |
| 처음 인원 | 4명 — 라이덴, 백은우, 에드워드, 오스카 (캐릭터 기획서 참고) |
| 제작 | 기획은 이 프로젝트, 디자인과 구현은 전부 Claude Code |

이전 기획인 YESTERDAY 스컬류 로그라이트는 이 게임의 마수 토벌 모드로 합쳤다. 앞서 만든 정통 대전 기획서는 이 문서로 대체한다.

## 확정 사항

- 전투는 블리치 vs 나루토식. 버튼은 공격, 점프, 대시, 기술 A, 기술 B, 필살 6개다.
- 공중 콤보를 넣는다.
- 대련은 1:1 단일 캐릭터다. 교대는 없다.
- 마수 토벌은 캐릭터 3명을 편성하고 판 도중에 바꿔 가며 싸운다.
- 평타는 캐릭터마다 다르다.
- 최종 그림은 코드로 그린 굵은 선 스틱맨 + 장식 + 이펙트다. 그림 시트 제작은 하지 않는다.
- 이펙트는 Sprite Fusion 픽셀 아트 VFX 수준을 기준으로 삼는다.
- 스프라이트는 64×64, 동작당 12~14프레임, 움직임은 완전히 부드럽게.
- 기획은 이 프로젝트에서, 디자인과 구현은 Claude Code에서 한다.
- 시스템을 먼저 기본 스틱맨으로 완성하고 캐릭터를 얹는다. 동작은 하나마다 직접 확인하고 승인한다.
- 마수 토벌은 결재의 달인과 연동하지 않고, 판이 끝나면 예산만 정산한다. 히어로와 빌런을 섞어 편성하고, 상성이 있다.

## 조작과 전투 시스템

버튼 6개와 방향만 쓴다. 커맨드 입력(↓↘→ 같은 방향 조합)은 없다. 휴대폰 터치로도 같은 조작을 할 수 있어야 한다.

| 입력 | 지상 | 공중 |
| --- | --- | --- |
| ← → | 걷기 (앞·뒤) | 조금 움직임 |
| ↓ 누르고 있기 | 방어 | — |
| 공격 | 연타하면 캐릭터별 4타 콤보 | 연타하면 3타 콤보 |
| ↑ + 공격 | 띄우기 | — |
| ↓ + 공격 | 쓸기 (맞으면 다운) | 내려찍기 |
| 점프 | 점프 | 2단 점프 (1회) |
| 대시 | 짧은 순간이동식 돌진 | 공중 대시 (1회) |
| 기술 A · 기술 B | 캐릭터 고유기, 기력 1칸 | 공중에서도 쓸 수 있는지는 캐릭터별로 정함 |
| 필살 | 기력 3칸을 모두 써서 쓰는 큰 기술 | — |

**방어와 가드 크러시**: ↓를 누르고 있으면 앞에서 오는 공격을 모두 막는다(상단·하단 구분 없음, 앉기 없음). 잡기는 없다. 대신 막을 때마다 방어 내구도가 줄고, 다 닳으면 방어가 깨져 잠깐 무방비가 된다. 내구도는 막지 않는 동안 다시 찬다.

**기력**: 3칸. 때리거나 맞을 때만 차고, 따로 모으는 버튼은 없다. 대시는 기력을 쓰지 않는다(제안).

**낙법**: 공중에서 맞고 있을 때 점프를 누르면 몸을 돌려 빠져나온다. 콤보 중 일정 횟수 이상 맞으면 낙법이 가능해져서, 공중 콤보가 무한히 이어지지 않는다.

**콤보 보정**: 한 콤보에서 많이 맞을수록 피해가 줄고(최소 35%), 공중에서 맞으면 조금씩 더 빨리 떨어진다.

**코드 구조 원칙**: 1초 60틱 고정. 모든 기술은 발동·지속·후딜레이를 틱 수로 정한다. 게임 계산에 무작위 값을 쓰지 않아, 같은 입력이면 같은 결과가 나오게 한다(온라인 대전에 필요).

## 공중 콤보 흐름

[embedded content: 공중 콤보 흐름 · 띄우기부터 기상까지]

공중 콤보의 기본 흐름이다. 캐릭터마다 평타가 달라서 어느 타에서 띄우고 어떻게 따라가는지는 캐릭터별로 다르다. 맞는 쪽은 많이 맞으면 낙법으로 빠져나갈 수 있어서, 콤보가 무한히 이어지지 않는다.

## 모드

두 모드는 같은 전투 시스템과 같은 캐릭터를 쓴다. 다른 것은 상대와 편성뿐이다.

|  | 대련 | 마수 토벌 |
| --- | --- | --- |
| 상대 | 다른 플레이어 (온라인), 연습용 CPU | 마수 (소형 무리 → 중형 → 대형 보스) |
| 편성 | 1명 | 3명, 판 도중 교대 |
| 승리 | 3판 2선승, 라운드 60초 | 구역을 돌파하고 마지막 보스 토벌 |
| 성장 | 없음 (실력 슸부) | 판 안에서 보상으로 강화, 판이 끝나면 예산 정산 |
| 규모 | 한 판 3~5분 | 전체 1시간 이상 |

**대련**: 방 코드로 두 사람이 만나 1:1로 붙는다. 입력만 주고받는 방식(딜레이 방식)으로 먼저 만들고, 느리면 롤백으로 바꾼다.

**마수 토벌**: 스컬류 로그라이트다. 히어로와 빌런 3명을 섞어 편성하고 출동한다. 현장에는 1명만 나가 있고, 나머지 둘과 바꿔 가며 싸운다. 편성 조합에는 상성이 있다. 민간 피해 같은 별도 리스크는 없다. 자세한 구조(구역 수, 보상, 예산 쓰임새)는 마수 토벌 기획서를 따로 쓴다.

## 무대와 파괴 (제안)

무대는 2140년 뉴 샌디에이고 도심이다. 세상이 망한 뒤 20세기 초 미국 도시풍으로 새로 지은 디스토피아 도시다. 미래 기술은 보이지 않는다. 벽돌 건물, 철제 비상계단, 노면전차, 가스등, 클래식 자동차, 칠한 간판이 거리를 채우고, 그 사이로 선전 포스터, 검문소 바리케이드와 철조망, 감시탑 서치라이트, 공장 굴뚝의 매연이 디스토피아 분위기를 만든다. 맵은 화면보다 훨씬 넓고, 싸우는 동안 도시가 부서진다. 부수는 맛은 연출과 재미를 위한 것이고, 부순다고 벌점을 받지는 않는다.

**맵 크기**

- 대련 맵은 화면 폭의 약 3배(960px)다. 카메라가 두 캐릭터를 따라가고, 두 사람은 화면 한 칸 안에서 벗어날 수 없다.
- 마수 토벌은 구역마다 더 길게 이어진 맵을 오른쪽으로 돌파한다.
- 바닥은 하나다. 공중 콤보가 있으므로 대련에는 발판을 두지 않는다(마수 토벌은 발판 허용 검토).

**부서지는 것**

| 대상 | 부서지는 모습 | 쓸 이펙트 |
| --- | --- | --- |
| 클래식 자동차·트럭 | 찌그러짐 → 불붙음 → 폭발 | Impact, Fire, Explosion |
| 노면전차 | 찌그러짐 → 탈선해 옆으로 넘어짐 (큰 물건) | Impact, Explosion, 먼지 |
| 가스 가로등·전신주 | 휘어짐 → 쓰러짐, 불꽃과 전기 | Impact, Fire, Lightning |
| 감시탑 서치라이트 | 깨져서 빛이 꺼짐, 불꽃 | Impact, Lightning |
| 검문소 바리케이드·철조망 | 부서져 날아감, 철조망이 끊김 | Impact, 먼지 |
| 선전 포스터 게시판 | 찢어짐 → 쓰러짐, 종잇조각이 날림 | Impact, Falling Leaves 응용 |
| 상점 간판·차양 | 찢어짐 → 떨어짐 | Impact |
| 쇼윈도 유리 | 금 → 산산조각 | Impact (파편) |
| 신문 가판대·우체통·나무 통 | 찌그러짐 → 날아감 | Impact, 먼지 |
| 소화전 | 부러지면 물기둥이 솟음 | Rain의 물보라 응용 |
| 벽돌 벽·바닥 | 금, 벽돌이 무너짐, 그을린 자국, 잔해가 남음 | Explosion, 먼지 |

- 부서지는 물건은 내구도가 있고 3단계(멀쩡 → 망가짐 → 파괴)로 모습이 바뀐다. 모두 코드로 그린다.
- 상대를 세게 날려 물건에 부딪히면 한 번에 부서지고, 부딪힌 쪽은 추가 피해를 입는다.
- 잔해, 그을린 자국, 깨진 유리는 라운드가 끝날 때까지 남는다. 싸울수록 도시가 엉망이 된다.
- 부서진 물건은 판정에 영향을 주지 않는 장식이다(온라인 동기화를 단순하게 하려고). 단, 어느 물건이 언제 부서졌는지는 게임 계산에 포함해 양쪽 화면이 같게 보이게 한다.

**건물 파괴**

- 건물 정면을 16×16px 덩어리 격자로 나누고 덩어리마다 내구도. 근처의 강한 타격, 날아온 캐릭터, 폭발이 범위 안 덩어리를 깎음.
- 깎이면 금 → 구멍 → 뚫림 3단계. 뚫린 자리 뒤로 실내(벽지, 계단, 가구, 배관)가 보이게.
- 아래층이 많이 뚫리면 위가 무너짐: 위 덩어리가 잔해로 떨어지고 큰 먼지 구름, 화면 흔들림, 짧은 슬로모션.
- 캐릭터가 건물 쪽으로 세게 날아가면 정면에 박히는 벽꽝(건물이 패이고 튕겨 나옴, 추가 피해).
  - 건물 쪽으로 날리는 것은 기술마다 정한다('벽 쪽으로 날림' 표시). 기본 스틱맨은 4타·기술 B·필살. 표시 없는 강타는 옆으로 날아간다.
- 덩어리 상태와 무너진 시점은 sim 상태(결정론). 파편·먼지는 렌더 전용, 떨어지는 잔해는 판정 없음.
- 파괴는 라운드가 넘어가도 유지해서 3라운드쯤이면 거리가 폐허가 되게. 부서지는 물건(자동차·가스등 등)도 똑같이 유지한다.

**벽꽝 → 다음 구역 (대련)**: 맵 끝 벽에 상대를 필살기나 강한 타격으로 박으면 벽이 무너지고, 두 사람이 옆 구역으로 넘어간다. 더 크게 부수는 맛을 주는 장치다.

**구역 후보**: 도심 대로(벽돌 건물과 노면전차 선로), 고가 철도 아래, 구역 경계 검문소, 항만 부두와 창고, 히어로 국 청사 앞 광장, 공장 지대, 밤의 옥상(급수탑과 감시탑). 구역마다 배경 이펙트(비, 안개, 불씨, 공장 매연)를 다르게 준다.

## 캐릭터 구성

캐릭터 하나는 동작 33개다. 그중 20개는 모든 캐릭터가 같이 쓰는 공통 동작이라 한 번만 만든다. 나머지 13개가 캐릭터 전용이다. 모든 동작은 12~14프레임이다.

**공통 동작 (20개)**

| 분류 | 동작 |
| --- | --- |
| 이동 (9) | 대기, 앞 걷기, 뒤 걷기, 점프, 2단 점프, 낙하, 착지, 지상 대시, 공중 대시 |
| 방어 (3) | 방어, 방어 막힘, 가드 크러시 |
| 피격 (6) | 약하게 맞음, 세게 맞음, 공중에서 맞음, 다운, 기상, 낙법 |
| 기타 (2) | 등장, 승리 |

**캐릭터 전용 동작 (13개)**

| 분류 | 동작 |
| --- | --- |
| 지상 평타 (6) | 1타, 2타, 3타, 4타, 띄우기, 쓸기 |
| 공중 평타 (4) | 1타, 2타, 3타, 내려찍기 |
| 기술 (3) | 기술 A, 기술 B, 필살 |

시스템을 만드는 동안에는 기본 스틱맨이 전용 동작 13개도 기본형으로 가진다. 캐릭터를 얹을 때 그 캐릭터 것으로 바꾼다.

**캐릭터 디자인으로 정하는 것**

- 이름, 소속(히어로·빌런), 능력 한 줄
- 대표 색과 장식 (머리 모양, 코트·망토 자락, 무기, 들고 다니는 물건)
- 평타의 성격 (주먹, 무기, 능력 중 무엇으로 싸우나)
- 기술 A·B와 필살의 내용, 쓸 이펙트
- 마수 토벌에서의 상성 (어떤 캐릭터와 같이 내면 좋은지)

## 비주얼

캐릭터는 단순하게, 화려함은 이펙트가 맡는다. 기준은 [Sprite Fusion 픽셀 아트 VFX](https://www.spritefusion.com/pixel-art-vfx) 수준이다.

**배경 색**: 녹슨 갈색, 회색 벽돌, 매연 뀝 하늘처럼 채도를 낮춘다. 밝은 색은 가스등과 서치라이트 불빛, 그리고 캐릭터와 이펙트에만 쓴다. 그래야 싸움이 배경에서 도드라진다.

**화면과 캐릭터 규격**

| 항목 | 규격 |
| --- | --- |
| 화면 | 320×180, 정수배 확대, 흐림 없음 |
| 캐릭터 칸 | 64×64, 발밑 기준점 (32, 61) |
| 캐릭터 키 | 약 52px |
| 선 굵기 | 팔다리 4px, 몸통 5px, 주변에 1px 어두운 외곽선 |
| 명암 | 빛을 받는 쪽을 한 단계 밝게. 뒷쪽 팔다리는 한 단계 어둡게 |
| 동작 | 동작당 12~14프레임. 뼈대와 관절 계산(IK)으로 포즈를 잡고, 키프레임 사이를 곡선으로 잇는다 |
| 색 | 캐릭터와 이펙트가 같은 제한 팔레트를 쓴다. 흐림 대신 디더링 |

굵은 선 스틱맨 위에 장식을 도형으로 얹어 인물을 구분한다. 장식은 뼈대에 붙어 있어서 어떤 동작에서도 모양이 흔들리지 않는다. 코트 자락이나 무기가 64×64 칸을 넘는 캐릭터는 칸을 96×96으로 키울지 따로 정한다.

**이펙트 배치**

| 쓰임새 | 이펙트 |
| --- | --- |
| 평타 타격 | Impact (불꽃, 파편, 먼지) |
| 베기 계열 공격 | Slash |
| 대시 | Dash & Blink (잔상, 빛으로 흩어지는 순간이동) |
| 기력 3칸 찬 상태, 각성 | Power Up (몸 윤곽을 따라 도는 오라) |
| 원거리 기술·빔 | Energy |
| 능력별 기술 | Fire, Lightning, Ice, Poison, Holy Light, Black Hole |
| 필살기·큰 타격·파괴 | Explosion |
| 방어 | Shield의 막는 연출을 짧게 응용 |
| 무대 분위기 | Fog, Embers, Rain |

이펙트는 파일 하나씩인 TypeScript 코드이고 MIT 라이선스다. Claude Code에 MCP로 연결해 가져오고, 색·크기·타이밍을 게임에 맞게 바꾼다. 목록에 없는 기술 이펙트는 같은 구조로 새로 만든다.

**연출 규칙**

- 맞는 순간 양쪽이 잠깐 멈춘다 (히트스톱, 약 7~12틱).
- 강한 타격은 화면 흔들림과 화면 번첍임을 같이 준다.
- 맞은 쪽은 몇 틱 동안 하얗게 번첍인다.
- 이펙트는 캐릭터 뒤와 앞 두 겹으로 나눠 그린다.
- 필살기는 화면을 어둡게 하고 기술 이름 컷인을 띄운 뒤 발동한다. 나중에는 AI로 만든 캐릭터별 컷씬 애니메이션으로 바꾼다. 캐릭터 대사는 넣지 않는다.
- 배경은 여러 겹으로 나눠 카메라와 다른 속도로 움직인다.

## 제작 방식

기획은 이 프로젝트에서 하고, 만드는 건 전부 Claude Code가 한다. 그림도 Claude Code가 코드로 그린다.

**Claude Code에 넘기는 문서**

1. 게임 기획서 (이 문서)
2. CLAUDE.md: 작업 규칙 (규격, 코드 구조 원칙, 승인 절차, 이펙트 라이브러리)
3. 동작 사양서: 동작마다 프레임 수, 자세 흐름, 판정 프레임, 이펙트
4. 작업 순서표: Claude Code에 하나씩 붙여 넣을 작업 지시

**동작 하나가 오가는 순서**

1. 여기서 동작 사양을 쓴다.
2. Claude Code가 그리고, 스프라이트 시트 PNG와 재생 화면을 만들어 직접 확인한다.
3. 직접 보고 고칠 점을 말하거나 승인한다.
4. 승인되면 다음 동작으로 넘어간다.

이 절차가 돌아가려면 Claude Code가 자기 결과물을 볼 수 있어야 한다. 그래서 가장 먼저 시트 PNG 출력, 대전 화면 캡처, CPU끼리 자동 대전 테스트를 만들게 한다.

**진행 단계**

1. **시스템**: 기본 스틱맨으로 전투 엔진, 공통 동작 20개, 기본형 전용 동작 13개, 이펙트, 넓은 맵과 파괴를 만든다.
2. **대련 온라인**: 방 코드로 1:1 대전을 연결한다.
3. **캐릭터 4명**: 여기서 기획하고 Claude Code가 장식과 전용 동작을 만든다.
4. **마수 토벌**: 마수, 구역, 3인 편성과 교대, 보상, 예산을 만든다.
5. **조정과 배포**
