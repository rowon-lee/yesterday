# 에이전트 무인 실행 (GitHub Actions + Claude Agent SDK)

Max 요금제의 월간 API 크레딧($100)은 Claude Code에는 쓸 수 없고 Agent SDK에는 쓸 수 있다. 그래서 GitHub Actions에서 Agent SDK로 작업을 돌려 크레딧을 쓴다. 휴대폰과 사지방 PC의 GitHub 웹만으로 실행하고 결과(PR)를 본다.

- 크레딧은 결제 주기가 끝나면 사라지고 다음 달로 넘어가지 않는다.
- 공식 Claude Code GitHub Action은 Claude Code 사용으로 잡혀 크레딧에서 빠지지 않는다. 그래서 직접 짠 Agent SDK 스크립트를 쓴다.
- 이 방식이 실제로 크레딧에서 빠지는지는 문서에 명시돼 있지 않다. 반드시 시험 실행 후 콘솔 결제 페이지에서 확인한다.

---

## 1. 한 번만 할 준비 (사용자)

1. **콘솔 작업 공간과 키**: platform.claude.com → 요금제와 연결된 조직에서 작업 공간(Workspace)을 새로 만든다(이름 예: github-actions). 작업 공간 지출 한도(Spend limit)를 걸고, 그 작업 공간에서 API 키를 만든다.
2. **GitHub 비밀값**: 저장소 → Settings → Secrets and variables → Actions → New repository secret. 이름 `ANTHROPIC_API_KEY_CREDITS`, 값은 방금 만든 키.
3. **Actions 권한**: 저장소 → Settings → Actions → General → Workflow permissions에서 "Read and write permissions"를 고르고 "Allow GitHub Actions to create and approve pull requests"를 체크.
4. **워크플로 만들기**: Claude Code(웹)에 아래 2장 지시문을 붙여 넣는다. PR을 머지한다.
5. **시험 실행**: 3장 순서대로 아주 작은 작업 하나를 돌리고, platform.claude.com → Settings → Billing의 크레딧 잔액이 줄었는지 확인한다. 줄지 않고 오류("Credit balance too low")가 나면 크레딧 대상이 아닌 것이니 멈춘다.

## 2. Claude Code에 붙여 넣을 지시문

```
GitHub Actions에서 Claude Agent SDK로 작업을 돌리는 워크플로를 만들어줘. 내가 GitHub 웹(휴대폰 포함)에서 실행하면, 에이전트가 저장소에서 작업하고 PR을 올리는 방식이야. 계획부터 보여줘.

1) .github/workflows/agent-run.yml
- 수동 실행(workflow_dispatch). 입력:
  task_file (기본 docs/tasks/next.md) — 지시문이 든 파일. 여러 줄 지시문을 웹 입력칸에 못 쓰니까 파일로 받는다
  note (선택, 한 줄) — 지난 결과에 대한 짧은 피드백. 지시문 뒤에 붙인다
  branch (기본 main) — 이어서 고칠 PR의 브랜치를 넣으면 그 브랜치에서 작업하고 같은 PR에 커밋만 추가한다
  model (기본 claude-opus-5-5), max_turns (기본 200)
- 권한 contents: write, pull-requests: write. timeout-minutes 180. 같은 브랜치 동시 실행 막기(concurrency).
- 순서: checkout → Node 설치 → npm ci → Playwright 브라우저 설치(npm run shot·sheets용) → node scripts/agent-run.mjs → 바뀐 게 있으면 커밋·푸시. branch가 main이면 agent/날짜-시간 새 브랜치로 올리고 gh로 PR 생성
- 키: secrets.ANTHROPIC_API_KEY_CREDITS를 ANTHROPIC_API_KEY 환경변수로. 공식 Claude Code GitHub Action(anthropics/claude-code-action)은 쓰지 마. 그건 API 크레딧 대상이 아니야.

2) scripts/agent-run.mjs
- @anthropic-ai/claude-agent-sdk의 query() 사용(devDependency로 추가)
- systemPrompt는 preset 'claude_code', settingSources ['project']로 CLAUDE.md를 읽게
- permissionMode 'bypassPermissions'(allowDangerouslySkipPermissions true), cwd는 저장소 루트, model·maxTurns는 입력값
- 지시문 앞에 이 규칙을 붙여:
  "이 실행은 무인 실행이다. 질문하거나 확인을 기다릴 수 없다. CLAUDE.md의 '계획부터 보여주기'와 '승인 대기'는,
   계획·한 일·확인한 미리보기 PNG 경로·틱 표를 .agent/pr-body.md에 쓰는 것으로 대신한다.
   지시문이 하나씩 승인받으라고 하면 첫 번째 단위만 끝내고 멈춘다. 확인 도구(npm run sheets·shot·simtest)는 그대로 돌린다."
- 끝나면 결과 메시지의 total_cost_usd와 토큰 사용량을 GitHub 작업 요약(GITHUB_STEP_SUMMARY)과 PR 설명 맨 아래에 적어
- PR 제목은 지시문 파일 첫 줄, PR 설명은 .agent/pr-body.md

3) docs/tasks/next.md 파일을 만들고 시험용 지시문을 넣어둬: "README.md 맨 아래에 '에이전트 실행 시험' 한 줄을 추가해줘."

만든 뒤엔 실행하지 말고 PR만 올려줘. 키는 내가 넣을게.
```

## 3. 실행하는 법

1. GitHub 웹에서 `docs/tasks/next.md`를 연필 아이콘으로 열어, 이번에 시킬 지시문을 붙여 넣고 커밋한다.
   - 지시문은 작업순서의 코드 블록을 그대로 쓰면 된다(예: 3-0b 라이덴 1차본 고치기).
2. 저장소 → Actions → "agent-run" → Run workflow → 입력값 확인 → 실행.
3. 끝나면 PR이 올라온다. 미리보기 PNG와 설명의 계획·틱 표·비용을 본다.
4. 고칠 점이 있으면 다시 Run workflow: `branch`에 그 PR의 브랜치 이름, `note`에 피드백 한 줄(예: "1타 감기를 더 길게"). 같은 PR에 커밋이 추가된다.
5. 괜찮으면 머지하고, 승인목록 기록까지 끝났는지 본다. 다음 단위로 넘어간다.

## 4. 비용 감각

- Opus 5.5 기준으로, 동작 하나를 만들고 시트·장면을 찍어 확인하는 실행은 대략 몇 달러 안팎으로 예상한다(정확한 값은 첫 실행의 작업 요약에 찍히는 total_cost_usd로 확인).
- 작업 공간 지출 한도를 걸어 두면 한도를 넘지 않는다. 크레딧이 떨어지면 다음 달 크레딧이 들어올 때까지 요청이 멈추고, 구독 요금으로 청구되지 않는다.
- 비공개 저장소라면 GitHub Actions 무료 실행 시간에도 한도가 있다. 실행이 길면 Actions 사용량도 같이 본다.

## 5. Claude Code(웹)와 나눠 쓰기

- Claude Code(웹, 구독 한도): 대화하며 정해야 하는 일, 계획을 보고 바로 방향을 바꿔야 하는 일.
- 에이전트 실행(크레딧): 지시문이 이미 확정된 일. 예: 동작연출지침서 9~13장처럼 수치와 순서가 다 정해진 수정 작업.
- 같은 브랜치를 두 곳에서 동시에 고치지 않는다. 캐릭터별로 나눠 맡기면 겹치지 않는다(예: 라이덴은 에이전트, 백은우는 Claude Code).
